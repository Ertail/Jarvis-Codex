05 / RISKS & GAPS

현재 저장소에서 먼저 바로잡아야 할 구조적 문제

플랫폼 이식과 별개로, 문서와 실제 파일 사이에 이미 드리프트가 보인다.

카탈로그 숫자 불일치

plugin.json은 스킬 6개라고 하지만 실제 SKILL.md는 9개다. README의 “총 21종” 설명과 현재 코어 6+역할 1+템플릿 4도 맞지 않는다. 수동 숫자 대신 생성형 inventory를 권장한다.

설치 상태 문서 드리프트

docs/agent-universe.md에는 install.sh와 README가 미완료 TODO로 남아 있지만 둘 다 존재한다. 변경 시 README만 확인하는 훅으로는 이 드리프트를 잡지 못한다.

훅의 거짓 양성/거짓 음성

테스트 파일이 저장소에 “하나라도” 있으면 통과하므로 변경 코드의 테스트 여부를 보장하지 못한다. 반대로 실험 코드에도 테스트를 강제해 흐름을 막을 수 있다.

과도한 확인 대기

첫 시도, 3단계, 3파일만으로 모두 중단하면 대부분의 실질 작업이 승인 대기로 바뀐다. 안전보다 상호작용 비용이 더 커지는 경계다.

도구·모델 이름의 빠른 노후화

claude-opus-4-8, Write|Edit|MultiEdit, Agent Team 환경변수처럼 런타임 세부를 역할 문서 전체에 박아 두면 마이그레이션 비용이 커진다.

merge 권한이 한 역할에 과집중

Weave의 git push . HEAD:master는 기술적으로 영리하지만, 검증·통합·기준 브랜치 전진을 한 에이전트가 모두 맡는다. branch/PR 또는 Handoff 중심이 감사 가능성과 복구성을 높인다.

추가하면 좋은 Codex 네이티브 요소

계층형 AGENTS

루트에는 공통 계약, 프론트/백/문서 디렉터리에는 가까운 규칙만 둔다. 잘못된 가정을 수정할 때 규칙을 갱신하는 피드백 루프도 포함한다.

플러그인 + Import 경로

Codex plugin manifest로 배포하고, Claude 설정 사용자는 Desktop의 Import로 instructions·skills·hooks·subagents를 변환한 뒤 검토하도록 한다.

커넥터/MCP 라우팅

GitHub·Slack·Drive·Notion 같은 사설 데이터는 웹 검색이 아니라 앱 커넥터/MCP를 쓰도록 skill에 명시한다. 인증과 권한 경계도 함께 문서화한다.

자동화/장기 작업 규칙

주기적 drift check와 장기 모니터링은 상시 에이전트가 아니라 automations·thread continuity로 분리한다.

명령 탐지 기반 검증

언어별 하드코딩 대신 package scripts, Makefile, CI 설정에서 프로젝트의 실제 검사 명령을 찾아 실행하는 verify skill을 둔다.

하네스 자체 eval

기존 67개 시나리오 자산을 살려 라우팅 정확도, 불필요 확인 횟수, subagent 사용 적절성, 검증 누락을 회귀 테스트한다.

06 / ROADMAP

권장 이식은 네 단계면 충분하다

처음부터 모든 Claude 기능을 재현하지 않고, 작은 코어에서 실제 사용 피드백으로 확장한다.

1Core

AGENTS.md 150~250줄 이내로 정체성, 안전, 변경 전 영향 분석, 변경 후 검증, 결과 보고만 옮긴다.

성공 기준: 단일 수정에서 추가 승인 없이 분석→수정→검증→보고가 완료된다.
2Skills

research, review, project-planning, document-delivery 4개 skill로 패턴·프로토콜을 통합한다.

성공 기준: 사용자가 skill 이름을 몰라도 목표 기반 description으로 자동 선택된다.
3Agents

explorer, reviewer, builder 3개 custom agent만 먼저 만든다. 명시 요청이나 skill 지시가 있을 때만 병렬 위임한다.

성공 기준: 읽기/테스트 병렬화는 빨라지고, 동시 편집 충돌은 증가하지 않는다.

08 / EVIDENCE

판단 근거와 범위

저장소의 실제 파일과 최신 공식 Codex 문서를 함께 사용했다. 점수는 상대적 의사결정 보조값이며 제품 벤치마크가 아니다.

분석한 저장소 근거
CLAUDE.md, agents, patterns, protocols, agent-protocol.md, settings.json, install.sh. 숨김 디렉터리를 포함한 전체 파일 목록과 주요 지침·스크립트를 읽었다.
Codex 공식 근거
AGENTS.md 계층과 32 KiB 기본 한도, App·CLI·IDE의 subagent workflow, managed worktree와 Handoff, 다른 에이전트 설정 Import, skills의 역할과 활성화, Codex plugin 패키징.
의도적으로 하지 않은 것
실제 Codex용 파일 변환·설치·전역 설정 변경은 수행하지 않았다. 이번 산출물은 “무엇을 어떻게 이식할지”에 대한 분석과 권장 설계이며, 모델별 비용·성능 벤치마크나 실사용 A/B 테스트는 포함하지 않는다.
이 리포트는 Ertail/Custom-Plugins@67cddeb01a4e를 기준으로 작성했다. 저장소가 바뀌면 inventory와 판정 수치를 다시 생성하는 것이 좋다.
